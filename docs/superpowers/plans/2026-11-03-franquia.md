# Franquia (prestígio) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The player can open a new branch (prestige) from level 12 on, keeping only the cars, and earn Selos de Franquia. The Selos buy permanent perks in a shop, so progression never ends.

**Architecture:**
- **Content:** the perk data lives in `content/prestige.json`, validated by the shared zod schema.
- **Rules:** a new pure module `packages/sim/src/prestige.ts`. It computes the seals, the perk factors, `openBranch` and `buyPerk`.
- **Where perks apply:** the existing reward, duration, patience and helper-cost code calls small boost helpers from that module.
- **Client:** a "Franquia" tab in the garage sheet, store methods, and a branch badge in the HUD.

**Tech Stack:** TypeScript 5.9, zod, Vitest 5, Phaser 3.90 with a DOM UI, Playwright 1.63.

**Spec:** `docs/superpowers/specs/2026-11-03-franquia-prestigio-design.md`

## Global Constraints

- **Branch formula:**
  - Open a branch at level ≥ **12**.
  - Seals = `floor(sqrt(runCoins / 500))`.
  - Errors: `level` below 12, `no_seals` when the seals would be 0.
- **What a new branch keeps and resets:**
  - Keeps `collection`, `prestige.seals` (plus the new seals), `prestige.perks`, `rngState` and `nextId`.
  - `prestige.branch` grows by 1.
  - Everything else is `createInitialState(c, now, …)`, with `runCoins = 0`.
- **Perks** (key, effect per level, max, baseCost, step):

  | key | effect per level | max | baseCost | step |
  |---|---|---|---|---|
  | `lucro` | 0.10 | 10 | 2 | 1 |
  | `agilidade` | 0.05 | 6 | 3 | 2 |
  | `paciencia` | 0.15 | 5 | 2 | 1 |
  | `experiencia` | 0.10 | 10 | 2 | 1 |
  | `recrutamento` | 0.15 | 4 | 3 | 2 |

  - The cost to reach level `n` is `baseCost + step × (n − 1)`.
- **Perk formulas:**
  - Coins: `floor(base × (1 + f))`, applied after the VIP 2× and after the helper share. Tip and timely bonus are not boosted.
  - XP: `floor(xp × (1 + f))`.
  - Duration: `max(1, round(durationS × (1 − f)))`. It stacks with the helper's training speed and does not change jobs already running.
  - Patience: `round(base × (1 + f))`.
  - Helper hire and training price: `ceil(price × (1 − f))`.
- **State:** `GameState.version` becomes `5`, with `prestige: { branch: number; seals: number; perks: Record<string, number>; runCoins: number }`. The v4 → v5 migration adds `{ branch: 1, seals: 0, perks: {}, runCoins: 0 }`.
- **Actions:** every new action does `tick` first and `touch` last, like the other actions.
- **UI copy:** Portuguese, everything in `strings.ts`.
- **Test IDs:** `tab-franquia`, `open-branch`, `confirm-branch`, `cancel-branch`, `perk-<key>`, `seals`, `branch`.

## Review Focus

1. **Opening a branch with jobs running, helpers on shift or a pending idle report.** Everything resets. No reward from the old branch is paid into the new one, and no welcome-back sheet appears. Covered in Task 3, test `open branch drops running jobs, helpers and the idle report`.
2. **Opening twice in a row** (double tap on confirm). The second call fails with `level` and grants no seals. Covered in Task 3, test `opening twice in a row only pays once`.
3. **A tampered save:** a perk above its max, a negative seal count, or an unknown perk key. Out-of-range values make the save `corrupt` (fresh start, as today), and unknown keys are dropped. Covered in Task 2.
4. **The garage sheet open on the Franquia tab when the branch opens.** The sheet closes. The level-down from 12+ to 1 fires no level-up celebration, and the next real level-up (to 2) still celebrates. Covered in Task 6, unit test on the controller level subscription.
5. **Perks bought mid-branch.** They affect only new jobs and new customers. Jobs already running keep their duration, and customers already in the queue keep their patience. Covered in Task 4, test `agilidade does not change a running job`.
